Security & credentials

Where are my passwords stored, and how safe are they?

In your operating system's keyring — Windows Credential Manager, macOS Keychain or the Linux Secret Service — so they are protected by your OS account like any other app's secrets. When the keyring isn't available, and on the Windows portable build, ZapTerm keeps an AES-256-GCM encrypted copy in its database instead, with a key created for that install. Passwords never appear in the interface, in session exports or in logs: sessions and macros refer to them by name and the backend types them for you.

There is no separate master password: whoever can use your OS account can use your saved credentials, just as with the keyring itself. With the portable build the key travels with the folder, so keep that folder (or USB stick) safe.

Can I manage reusable credentials?

Yes. The credential vault holds named credentials (user and password) that you can add, edit and delete. Sessions, login scripts and macros point at a vault entry, so changing a password there changes it everywhere it's used.

What happens to my credentials in backups and sync?

The encrypted backup — and the sync folder, which uses the same format — includes credentials, sealed with a passphrase you choose: the passphrase is stretched with Argon2id (memory-hard, which makes guessing it offline expensive) into an AES-256-GCM key, and the file's header is authenticated so it can't be tampered with. Your cloud provider only ever sees ciphertext. The plain JSON session export never contains passwords.

Does a session export contain anything secret?

Passwords are never exported. Login scripts are exported as they are, though, so a send step where you typed a secret yourself travels with the file — ZapTerm warns you about this before exporting. Use vault references in login scripts to keep secrets out of exports.

How does ZapTerm check SSH host keys?

On the first connection it shows the server's SHA-256 fingerprint for you to approve. The key is then pinned in known_hosts, and a different key on a later connection is flagged instead of accepted silently.

Do session logs record passwords?

Session logs record what the terminal receives. Devices don't echo a password you type at a password prompt, so it doesn't appear in the log; anything a device does print (a configuration shown in clear text, for example) is recorded like any other output.

Connecting & sessions

Which kinds of connection does ZapTerm support?

SSH, Telnet, serial consoles and local shells (on Windows also PowerShell, Command Prompt and WSL distributions). Saved sessions can be organised in folders, tagged and searched; Quick Connect opens a host without saving anything.

Which SSH authentication methods work?

Password, public key, the SSH agent and keyboard-interactive, which covers most two-factor prompts. The password can come from the credential vault so it is never typed or shown.

Can I go through a jump host?

Yes. A session can be routed through another saved session, like ProxyJump.

Does it do port forwarding and SFTP?

Yes, over SSH: local (-L), remote (-R) and dynamic SOCKS5 (-D) forwards, which can start automatically when the session connects, and an SFTP browser to upload, download and edit remote files with your own editor.

Can I bring my sessions from another tool?

Yes: ~/.ssh/config, PuTTY (registry or .reg export), MobaXterm (MobaXterm.ini or .mxtsessions) and SecureCRT (its Sessions folder), with folders, jump hosts, keys and tunnels where the source has them. ZAPX data is imported on first run.

Can I work on several devices side by side?

Yes. Split a tab into panes as many times as you like, open a group of hosts as a grid, and broadcast what you type to all of them. Compare shows their output together so differences stand out.

Command lists, hints & highlighting

Which vendors have command lists?

FortiGate, Cisco IOS / IOS XE, Cisco IOS XR, Arista EOS, Juniper Junos, Linux, macOS and Windows. The bar under the terminal shows the lists for the platform ZapTerm detected on that tab, plus ★ Custom (your own commands, on every platform) and Recent.

Can I change the built-in command lists?

Yes. In Settings → Command Lists, "Make my copy" writes that platform's list as a JSON file you can edit with any text editor; ZapTerm uses your copy from then on and updates never change it. For commands you use everywhere, add them to ★ Custom in the bar.

Where do the suggestions while I type come from?

From your own command history and from per-vendor catalogs. The platform is detected from the device's banner and prompt, so the suggestions match the device you are on. Accept a suggestion with → or End, or open the list with Ctrl+Space.

Can I change what gets highlighted?

Yes. Settings → Highlight Rules lists every rule (a word or a regular expression, a colour, bold or underline); you can add, edit and delete them, and export or import them as a JSON file (importing skips rules you already have). The defaults colour interface states, IP addresses, usage percentages, sizes, dates, URLs and good or bad status words.

Automation

Can I push configuration to many devices at once?

Over SSH and Telnet, yes: broadcast types into a whole group of sessions at once; Tools → Send command list… sends a list of commands line by line to the open sessions you pick; and Python scripts can open sessions, send commands and check the output across as many devices as you like — starting in Dry run (nothing sent), then Read-only, then Run.

What do I need to run Python scripts?

Python 3.9 or newer on the same computer. ZapTerm runs your script with it and puts its own zapterm module on the path, so a script needs nothing else; you can still use any library you have installed.

Can a script read my passwords?

No. A script can ask ZapTerm to type a vault credential into a session (send_secret), but the password itself never reaches the script.

What are Dry run and Read-only?

Two safe ways to try a script. In Dry run nothing is sent or opened: every action is listed as "would …". In Read-only, sessions are opened and display commands (get and show by default) run for real, while anything else is skipped and logged. ZapTerm enforces both, not the script.

Can I use a Jupyter notebook or VS Code?

Yes. Turn on Tools → Allow notebook connection…, then import zapterm and zapterm.connect() from a notebook or a Python prompt you started yourself. Every call is carried out on a real ZapTerm tab, so you see it happen.

Does ZapTerm support NETCONF or RESTCONF?

Not built in: ZapTerm is a terminal (SSH, Telnet, serial). Scripts run on your own Python 3, though, so a script can use libraries you install yourself, such as ncclient for NETCONF or requests for RESTCONF, next to ZapTerm's own module for the terminal sessions.

Privacy, updates & licence

Does it send any data anywhere?

No. There is no account, no telemetry and no automatic update check: the app only connects to the devices you open. (This website asks GitHub for the latest release to point the download buttons at it.)

How do I update ZapTerm?

Help → Check for updates… shows the version you have and opens the releases page, where you download the new version. Nothing is checked or downloaded in the background.

Is it really free?

Yes. ZapTerm is free software under the GPL-3.0-or-later licence: no paid edition, no account and no limits. The source is on GitHub.

What happened to ZAPX?

ZapTerm continues ZAPX, which is frozen at version 0.42.1. ZAPX data is imported on first run, so you can carry on where you left off.
